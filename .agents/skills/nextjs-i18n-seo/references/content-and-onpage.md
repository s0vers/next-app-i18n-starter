# Content and on-page SEO

Use this playbook when the work concerns what a page says, which audience it serves, how pages relate, or how search results describe them. Technical markup cannot compensate for pages that do not meet a real audience need.

## Build the page around a search task

1. Identify the audience, task, and decision the page helps with. Ask what the visitor needs to know or do after arriving.
2. Research the target market and current results when the request requires keyword selection, competitive analysis, or claims about search demand. Use primary audience or product data where available. Keep tool estimates labeled as estimates.
3. Choose one clear page purpose. If two intents need different answers, use separate pages only when each can provide distinct value and has a useful path between them.
4. Put the direct answer and essential information in crawlable page content. Organize it with descriptive titles, headings, paragraphs, lists, and ordinary links.
5. Add first-hand detail, evidence, examples, or product specifics that make the page useful beyond a generic summary. Verify factual claims and identify their sources where readers need them.
6. Review the page as a reader: does it resolve the task, explain limits, and give the next useful action? Revise or consolidate content that leaves the reader searching again.

## Page elements

- **Title:** Write a unique, concise title that identifies the page's main subject. Make it match the visible heading and content. Google may generate a different title link when the provided title is inaccurate, stale, or unclear.
- **Description:** Summarize the specific page for a potential visitor. Treat the description as a snippet suggestion; search engines may select text from the page instead.
- **Headings:** Use a clear main heading and descriptive section headings. Headings should describe the section that follows, not repeat keyword variations.
- **Links:** Link to important pages with crawlable anchors that describe the destination. Build paths from navigation and related pages so visitors and crawlers can find the content.
- **Images and media:** Use relevant assets that add information. Write concise alt text for the image's purpose in context; leave decorative images with empty alt text. Follow the dedicated image or video guidance when those surfaces matter.
- **Dates and authorship:** Show dates, authors, credentials, and update claims only when accurate. Change dates when the substance changed, not to create a freshness signal.
- **Structured data:** Consider it only when a supported search feature fits the page and the markup matches visible content. It can establish eligibility; it does not promise a rich result or improve rankings by itself.

## Localized content

Translate and review the content for the audience, not just the metadata. Research local terminology and intent before adapting titles or adding market pages. Read [International SEO](international-seo.md) for URL, `hreflang`, and regional requirements.

## Avoid low-value expansion

Do not generate near-identical pages for every keyword variation, location, question, or locale. Do not add a word-count target, forced FAQ block, keyword list, or repeated summary unless it helps the visitor. Consolidate overlapping pages when they serve the same task and do not add distinct value.

When generative AI helps draft copy, verify facts and add human expertise, first-hand detail, and editorial review. Review the current search engine spam policies before automating large-scale publication.
